# DESIGN —— 标签排序、树操作布局与跨平台 Hot Exit

需求日期：2026-08-11 · slug：`tab-tree-hot-exit`

## 1. 已确认的产品语义

- 拖拽文档标签只改变标签顺序，不改变活动文档；顺序随会话恢复。
- 整个标签主体可拖拽，关闭按钮除外；拖动反馈包括影像、插入线和边缘自动滚动。
- 本轮不提供键盘标签排序。
- 树节点操作跟随内容排列；值摘要过长时先截断，操作按钮保留在可视区域。
- 树节点操作仍只在行悬停或键盘聚焦时显示。
- 桌面版采用 Hot Exit：会话可恢复时正常退出不询问未保存内容；不可恢复时才警告。
- macOS `Command+Q`、Windows 标题栏关闭和 `Alt+F4` 使用同一关闭语义。
- 真正由系统强制终止进程不承诺零丢失，只恢复最近一次完整会话提交。

领域语言见仓库根目录 `CONTEXT.md`，原生会话存储决策见
`docs/adr/0001-native-session-manifest-and-document-snapshots.md`。

## 2. 已核实的根因

### 2.1 标签无法排序

`AppHeader.tsx` 直接按 `documents.map` 渲染标签，工作区 store 没有重排动作。
`documents[]` 本身已经是标签顺序的唯一真值来源，并会随现有会话恢复，因此无需新增独立排序字段。

### 2.2 树节点操作被推到最右侧

`.tree-subtree-actions` 使用 `margin-left: auto`，而树内容容器使用 `min-width: max-content`。
两者共同把展开子树、收起子树和复制操作推到整行或横向内容的末端。短内容与按钮之间出现大块空白，
长内容下按钮还可能落在当前视口之外。

### 2.3 Windows 确认退出后再次触发关闭请求

当前 `onCloseRequested` 在用户确认后调用 `appWindow.close()`。Tauri API 明确说明 `close()` 会再次发出
`closeRequested`，而 `destroy()` 才是不再发事件的强制关闭原语。现有布尔引用试图绕过第二轮事件，
但把退出正确性建立在递归事件与 React 生命周期时序上，Windows 标题栏关闭已出现无法完成的问题。

### 2.4 `localStorage` 无法支撑 Hot Exit 承诺

现有工作区持久化是同步 `localStorage`，超过约 4 MiB 时会主动丢弃全部文档内容，只保留设置和最近文件。
这与“重启后恢复全部标签和未保存内容”冲突，也无法为正常退出提供异步写入成功与否的明确结果。

## 3. 模块设计

### 3.1 文档标签重排

在 workspace store 增加 `reorderDocument(id, targetIndex)`：

- 输入是被拖文档 id 和移除该文档后的目标插入下标。
- id 不存在、下标归一化后位置未变化时返回 `false` 且不触发持久化。
- 只重排 `documents`；`activeDocumentId`、`diff`、内容和脏状态保持不变。
- 新数组沿用现有工作区持久化通道，因此浏览器和桌面会话都自然保存顺序。

`AppHeader` 使用桌面 WebView 支持稳定的原生 HTML Drag and Drop：

- `draggable` 只放在标签主体，不放在关闭按钮。
- `dragstart` 保存源文档 id；浏览器超过原生移动阈值后才进入拖动，普通点击仍切换文档。
- `dragover` 根据指针相对目标标签中点计算 before/after，并渲染 2px 插入线。
- `drop` 归一化“先移除源项、再插入”的下标，只在落下时提交 store。
- 拖动源使用透明度变化，不使用缩放，避免标签栏布局跳动。
- 指针接近 `.tabs-scroll` 左右边缘时以 `requestAnimationFrame` 自动滚动；结束、取消和卸载时清理帧。
- 内部 drop 必须 `stopPropagation()`，避免冒泡到全局 JSON 文件拖放处理。

### 3.2 树节点操作布局

保持现有 DOM 顺序“展开按钮 → 路径 → 值摘要 → 子树操作 → 复制”，只调整弹性规则：

- 删除 `.tree-subtree-actions` 的 `margin-left: auto`。
- 树行占满可视宽度并允许路径/值区域收缩；操作按钮 `flex: 0 0 auto`。
- 值摘要 `min-width: 0` 且保留 ellipsis，短内容不拉伸占满剩余空间。
- 子树操作与内容固定留 8px，展开和收起合并为一个状态自适应按钮：子树未完全展开时递归展开，
  已完全展开时递归收起；复制按钮紧随其后。
- hover/focus 显示规则、28px 行高、虚拟列表绝对定位和键盘树操作保持不变。
- 不引入新颜色或图标；插入线复用现有 `--accent`，亮暗主题都必须可辨认。

`ui-ux-pro-max` 的检索结果中，营销式“鲜艳块状/横向旅程”与现有工作台不匹配，明确不采用；
本轮只采用稳定 hover、可见 focus、无布局位移和行为测试等通用 UX 约束。

### 3.3 原生会话存储

新增 Rust Tauri 命令，所有应用数据目录读写均在后端完成，不扩大前端 `fs` capability：

```text
AppData/session-v1/
├── manifests/
│   ├── manifest-00000000000000000001.json
│   └── manifest-00000000000000000002.json
└── documents/
    └── doc-<document-id>/
        ├── snapshot-<snapshot-id>.json
        └── ...
```

文档 id 与快照 id 分成两个带固定前缀的路径分量，避免两个 128 字符标识拼接后超过 Windows
单文件名上限，也避免合法标识恰好命中 `CON` 等 Windows 保留文件名。

一次提交按以下顺序执行：

1. 校验所有 id、snapshot id 和清单引用，禁止路径穿越。
2. 只把内容发生变化的文档写成新的唯一版本文件；临时文件写完后重命名到唯一目标名。
3. 确认清单引用的全部文档版本存在。
4. 最后发布新的递增 generation 清单；目标文件名唯一，不依赖 Windows 的覆盖重命名行为。
5. 成功后保留最近两个完整清单，并按两个清单的引用集合清理孤儿文档；清理失败不使提交失败。

加载时按 generation 从新到旧检查清单，返回第一份语法有效且全部文档引用可读取的版本。
最新清单损坏或缺文件时自动回退上一份完整清单，不拼接不同 generation。

### 3.4 前端会话协调器

新增独立于 Zustand store 的会话协调器，负责异步原生 I/O、调度和提交状态：

- Tauri 环境不再把文档写入现有 `localStorage`，避免 4 MiB 误报和重复大对象存储。
- 启动时先加载原生会话；若不存在，则读取并校验旧 `localStorage` 会话，完整提交后再 hydrate store。
- 旧 key 暂留但不再读取；只有原生目录为空时才允许迁移，避免旧数据覆盖新会话。
- 协调器保存每个文档最后提交的字符串引用与 snapshot id，只通过 IPC 发送变化文档。
- 标签顺序、活动文档、设置等元数据变化只发布新清单，不重写未变化文档内容。
- 停止变化 750ms 后提交；从首个待提交变化起最长 5s 强制提交一次。
- `blur` 和正常退出调用 `flush()`，等待正在进行的提交并继续提交其间产生的最新状态。
- 所有提交串行化；写入期间出现的新变化合并到下一次提交，不允许旧响应覆盖新状态。

浏览器模式继续使用现有同步 `localStorage` 实现及其容量提示，不调用 Tauri 命令。

### 3.5 Store hydrate 与启动顺序

workspace store 增加一次性的 `hydrateWorkspace(snapshot)`，复用现有 sanitize 规则：

- 原生会话加载完成前显示简单的工作区加载状态，不允许编辑空白临时文档。
- 有原生会话时用其替换启动占位状态；无会话时保留默认空白文档。
- 恢复失败时保留空白文档、展示明确错误，并把当前会话标记为不可恢复。
- 浏览器模式保持同步初始化，不增加加载闪烁。

### 3.6 正常退出与失败策略

Tauri `onCloseRequested` 处理器必须同步调用 `event.preventDefault()`，随后：

1. `await session.flush()`。
2. 若启用了会话恢复且 flush 成功，直接 `appWindow.destroy()`。
3. 若没有未保存文档，即使快照失败也允许关闭。
4. 若存在未保存文档，且会话恢复关闭或 flush 失败，只显示一次危险确认。
5. 用户取消则留在应用；确认“仍要退出”后调用 `destroy()`，不再调用 `close()`。

单独关闭某个未保存文档仍保留现有确认，因为该动作会主动从后续会话快照删除文档，Hot Exit 不能替代它。
浏览器 `beforeunload` 保持同步保护逻辑。

## 4. 测试与验收

### 4.1 自动化测试

- Store：跨多个位置重排、同位 no-op、活动文档不变、Diff 引用不变、恢复后顺序一致。
- AppHeader：before/after 落点、关闭按钮不触发拖拽、drop 后回调一次、取消拖动清理状态。
- TreeView/CSS 守卫：单个子树按钮按完整展开状态切换；短值操作不再 auto 推右；长值可收缩；
  hover/focus 规则不回退。
- 会话协调器：750ms debounce、5s max wait、串行合并、blur/flush、失败状态和旧会话迁移。
- 关闭策略：可恢复时不提示；恢复关闭或写失败且存在脏文档时提示；确认后走 destroy。
- Rust：首次提交/加载、增量文档、损坏最新清单回退、未提交孤儿忽略、清理保留上一代、非法 id 拒绝。

### 4.2 真实界面检查

- 1440×900 与 1024×768：拖动多个标签，确认插入线、活动文档和横向滚动。
- 1440×900 与 375×812：树视图短值/长值/长键，确认按钮靠近内容且不互相遮挡。
- 明暗主题分别检查插入线、拖动源、树按钮 hover/focus。
- Playwright 只覆盖浏览器可见交互；Windows 标题栏关闭与 `Alt+F4` 由 Windows CI/安装包验收。

## 5. 不在本批次范围

- 标签排序的键盘快捷键或命令面板命令。
- 浏览器会话突破 `localStorage` 配额。
- 操作系统强制结束进程时的零数据丢失保证。
- 多窗口会话合并；当前产品只有 `main` 窗口。
- 云同步、文件自动保存或把会话快照当作用户文件备份。
